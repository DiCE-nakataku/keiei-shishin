# Refactor Audit (Phase 0)

調査日: 2026-11-21<br>
対象: `v1.3.1-excel-verified` のローカル作業コピーとその既存テスト・設定<br>
制約: Phase 0 のため、アプリコード・設定・依存関係は変更していない。

## 技術構成と開発コマンド

- ブラウザーで動作する静的HTML/CSS/JavaScriptアプリ。メインUI、スタイル、業務フロー、ページ生成の大部分は `index.html`（約3,133行）にインラインでまとまっている。
- 数式処理は `src/recalc.js`（fast-formula-parser 1.0.19を利用）、ビルド成果物は `dist/formula-engine.js`。依存は `package.json` / `package-lock.json` で管理。
- 発表モードは `motion/` 以下の別JS/CSSに分離されている。SheetJSは `vendor/` に同梱。
- `npm test`: `node tests/recalc.test.mjs`。この調査時は13件すべて成功。
- `npm run build`: `scripts/build.mjs` が `dist/`, `vendor/`, `licenses/` を生成・更新する。Phase 0では生成変更を避けるため実行していない。
- `package.json` にあるスクリプトは `test` と `build` のみ。lint、型チェック、start/serverのスクリプトはない。READMEでは `index.html` を直接ブラウザーで開く手順を案内している。
- ブラウザー/PDF確認用に `tests/motion_browser.py` と `tests/excel_pdf_integration.py` があるが、`npm test` からは実行されない。今回のPhase 0では実行していない。直近の実行記録ではPlaywrightのNode子プロセスがWindows `WinError 5` で起動できず、実ブラウザー検証が環境依存になっている。
- 作業コピーのプロジェクト直下に `.git` がなく、`git status` は「not a git repository」で失敗する。したがってこのコピー単独ではブランチ・未コミット差分・履歴を確認できない。Phase 1以降はリモート `main` と一致するGit checkout/worktreeを先に用意する必要がある。

## 主要なユーザーフロー

1. ランディングで空のベースシートまたはサンプル一式を取得する。
2. 入力済みExcelをファイル選択またはドラッグ＆ドロップで読み込む。
3. 数式をブラウザー内で再計算し、入力値・計算結果を複数ページへ表示する。数式エラーがあれば一覧を表示し、印刷を止める。
4. 表紙ロゴ、10年ビジョン画像、テーマカラーを調整する。
5. 発表モードでページ移動・演出速度・全画面表示を操作する。
6. ブラウザーの印刷ダイアログからA4横PDFを保存する。
7. 別ページ `motion/index.html` でモーション効果の見本を閲覧する。

認証、登録、決済、バックエンドAPI、DBを使うフローは対象コードから確認できなかった。Excelはブラウザー内で処理する設計だが、Google Fontsの取得先へのネットワークリクエストはある。
